# Kiran Shahi ? Visual Brand Direction

## Core idea

**Precision with curiosity.** The brand should feel like a product engineer's research notebook: technically rigorous, calm, practical, and open to exploration.

## Positioning line

> Software Engineering ? Visual Computing ? Applied AI

Use this descriptor consistently on social cards, profile summaries, and short biographies.

## Visual principles

1. **Editorial first, technical second** ? generous whitespace and readable hierarchy come before decorative technology motifs.
2. **Evidence over spectacle** ? use real product screenshots, results, publications, and interactive work.
3. **Structured curiosity** ? grids, point fields, measured lines, and geometric diagrams suggest exploration without looking like generic AI imagery.
4. **One green signal** ? forest green highlights actions, labels, links, and small identifying details. It should not dominate entire pages.

## Colour system

| Role | Light | Dark | Usage |
|---|---|---|---|
| Paper | `#f7f7f4` | `#101512` | Page background |
| Ink | `#17201d` | `#f2f4f1` | Headlines and primary text |
| Signal green | `#126b55` | `#7ad1b3` | Actions, links, labels, brand mark |
| Sage | `#edf2ee` | `#1d2822` | Technical surfaces and diagrams |
| Muted | `#65706b` | `#a4aea8` | Supporting copy |

## Typography

- **Display:** Georgia or an equivalent editorial serif for names, headlines, and project titles.
- **Interface/body:** Inter, system UI, or Segoe UI for navigation, metadata, controls, and body copy.
- Use compact uppercase sans-serif labels with generous letter spacing for categories and technical metadata.
- Avoid more than two type families.

## Brand mark

The primary mark is the `KS` monogram in a compact green square. Use it as an identifying detail in navigation and footer?not as a large decorative logo.

## Graphic language

- Fine technical grids at very low contrast.
- Point-cloud fields, orbit lines, and measured geometric constructions.
- Short green rules and small nodes for emphasis.
- Warm off-white surfaces instead of pure white.
- Restrained shadows; borders should define most components.

Avoid glowing circuits, robot heads, brains, neon gradients, code rain, or generic AI stock imagery.

## Project imagery

1. Prefer real application screenshots.
2. Use consistent wide crops and quiet backgrounds.
3. When a screenshot is unavailable, use the code-native project visual system: a large two-character discipline code, a small technical label, and a subtle geometric field.
4. Never invent results, clients, or interfaces for presentation value.

## Interaction

- Motion should be subtle: 1?2 px lift, small image scale, and short underline transitions.
- Retain visible keyboard focus.
- Respect reduced-motion preferences.
